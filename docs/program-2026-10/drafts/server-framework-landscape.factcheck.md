# Fact-check: server-framework-landscape

Checked 2026-10-05 against the draft `server-framework-landscape.js`, its `.sources.md`, and the brief section in `briefs/topics.md`. The draft was not edited.

## Verdict: PASS WITH FIXES

- WRONG: 5 (NGO 2.0.0 Unity targets; Fusion shared-mode authority; Ably "200 connections a month"; Agones "does not describe matchmaking"; Photon 20,000 CCU "a sales conversation").
- UNSUPPORTED: 4 (Hathora shutdown facts stated without a hedge in the body; Fusion shared mode "very high player counts"; Nakama on Postgres; where the NGO topology setting lives).
- OUTDATED: 2 (Netcode for Entities 1.8.0 and NGO 2.0.0 are quoted as the documentation versions; both packages are many releases further on).
- Most serious issue: both authority snippets say the server decides, but they accept client-supplied values. Any client can call `HitRpc(50)` on any player's `Health` as often as it likes. The Go room applies any `Dx`/`Dy` a client sends. The Unity snippet also does not compile, because `Mathf` needs `using UnityEngine;`.

Repetition: there is no factual overlap with the sibling drafts. A grep for Hathora, Photon, Quantum, Fusion, Socket.IO, Firebase, Edgegap and Mirror found one unrelated Mirror mention in bandwidth-and-interest-management. There is a moderate overlap with the published topic `server-stack-choices`. how[4] (your own interface between the game and the vendor), how[7] (record the exit cost), traps[1] (a free tier is not a price), traps[4] (vendor types leaking into rules) and why[3] (services end) restate its how[5], how[7], traps[2], traps[1] and why[1]. ## Code issues

Go was not compiled (Go is not installed). It was read line by line against Go 1.23. Godot and Unity APIs were checked on the official reference pages listed above.

- **Unity (ENGINE unity.snippet): does not compile.** `Mathf.Max` is in `UnityEngine`, and the file has only `using Unity.Netcode;`. Add `using UnityEngine;`. All other APIs are confirmed: `NetworkBehaviour`, the `NetworkVariable<int>` constructor with read and write permissions, `[Rpc(SendTo.Server)]` and the `Rpc` suffix. The target-typed `new(...)` needs C# 9, which Unity 6 supports.
- **Unity: the server does not really decide.** `HitRpc` is `SendTo.Server` "regardless of ownership". Any client can call it on any player's `Health` with `damage = 50`, as often as it wants. The `0..50` range check does not make "the server decides whether the hit counts" true. The server should decide that a hit happened, from the attacker's weapon, cooldown and line of sight, and compute the damage itself. Fix the comment, or let the client send only "I fired" and have the server compute the hit.
- **Go (GO.snippet): compiles as read.** Both imports are used. `for drained := false; !drained; {` is a valid for-clause. The `[2]int` value copy and write-back are correct. The map copy is deep enough because arrays are values. There are two defects:
  1. If `in` is closed, `case i := <-in` is always ready with a zero `Input`. The drain loop then never sets `drained` and the tick goroutine spins forever. Use `i, ok := <-in; if !ok { return }` (or set `in = nil`).
  2. The comment says inputs are "never on the client's say-so", but the code applies any `Dx`/`Dy` the client sends. A client sending `Dx: 1000` teleports. Clamp to a per-tick maximum to match the comment. `tickRate <= 0` panics in `NewTicker`. That is acceptable for a sketch and is not flagged.
- **Godot (ENGINE godot.snippet): APIs confirmed.** These are `ENetMultiplayerPeer.create_server(port, max_clients = 32, ...)`, `MultiplayerSpawner.spawn_function`, `spawn(data: Variant = null) -> Node`, `MultiplayerAPI.peer_connected(id: int)` and `Node.set_multiplayer_authority(id, recursive = true)`. The snippet relies on the `Spawner` node's `spawn_path` being set in the scene. Say so in the comment, because `spawn()` errors without it.

## Teaching issues

- **The authority snippets contradict the authority lesson.** The Unity and Go snippets claim server authority but trust client values (see Code issues). This topic's main point is "who is allowed to be wrong", so the examples should demonstrate the rule they state.
- **The DIAGRAM puts frameworks in the wrong families.** "Mirror host" sits under "Shared or client authority". Host mode is a listen server, which is server-authoritative with a trusted host player, so it belongs in the server row with a "host can cheat" note. "Agones fleets" sits under "Game backend with match handlers". Agones is hosting and orchestration. It runs no match logic.
- **trade[1]: Quantum "every player count scales cheaply" overclaims.** Every client receives every player's input, and every client simulates the whole world, so client CPU grows with entities and players. The documented cap is 128. Say "bandwidth stays small up to the documented 128 players".
- **mid Q1 against tech[1] on hidden information.** mid Q1 says Quantum "offers no hidden information". tech[1] says it is "awkward". Use tech[1]'s wording.
- **junior Q1 strengthens the DA warnings.** It drops Unity's hedges ("depending on the platform", "that require an accurate predictive motion model").
- **traps[5] cites only the 2019 benchmark.** Mirror's README also lists a 2022 400-800 CCU test. The lesson stands, but cite both or say "the oldest of its benchmarks".
- **Two style points.** junior Q3 says "excellent for chat", which is a hype word: use "fits chat". why[2] says "one number" and then gives two.

## Missing coverage (brief "Must cover")

- **The mechanism matrix is thin.** The brief asks for a matrix with authority model, topology, sync model, prediction/rollback, hosting, scale ceiling and licence/cost for each named framework. The DIAGRAM is a 5×2 matrix of families with only Examples and Pays-off columns. Mirror, Fish-Net, Godot, Steamworks and EOS do not appear in it. Licence and cost are missing for Unreal, Godot and NGO/NfE in the body.
- **NGO's prediction support is never stated.** NGO has no built-in client prediction, unlike NfE. That is the most decision-relevant Unity fact, and only the Godot `map` note implies it.
- **Fish-Net is only named.** It has one FACTS line and two lists, and no mechanism text (prediction support, transports).
- **Unreal Replication Graph** appears only in FACTS. The difference between Replication Graph and Iris is not explained.
- **"How to choose by game type"** is covered implicitly through the `fit` fields and the diagram's "Pays off when" column. An explicit game-type → family pass in `how` would close it.
- Pusher appears only as a category, with no source. That is acceptable, and the writer says so.
