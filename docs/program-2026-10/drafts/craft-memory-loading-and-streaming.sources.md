# Sources: craft-memory-loading-and-streaming

R = read the source page itself (fetched; the fetch tool summarises, so wording is paraphrase). S = search summary only. C = arithmetic or general knowledge, no single source.

- Apple os_proc_available_memory returns memory left before the system terminates the app. https://developer.apple.com/documentation/os/os_proc_available_memory (R)
- Uncompressed 2048x2048 RGBA8 = 16 MiB (4 B x 4,194,304); with mips x 4/3 = about 21.3 MiB. (C)
- Unity: mipmaps add 33 percent on disk and in memory; Mipmap Streaming controls runtime loading. https://docs.unity3d.com/6000.0/Documentation/Manual/texture-mipmaps-introduction.html (R)
- ASTC 6x6 is about 1.8 MiB for 2048x2048 before mips: relies on ASTC using 128 bits per block (3.56 bits per pixel at 6x6). NOT fetched; fact-checker to confirm against https://registry.khronos.org/DataFormat/specs/1.3/dataformat.1.3.html#ASTC or Arm's ASTC documentation. (C)
- 48 kHz, 16-bit, stereo PCM = 192,000 B/s; ten minutes = 115.2 MB. (C)
- Epic: generating a PSO on demand can take 100 ms or more; Graphics and Compute PSOs cached; ray tracing PSOs not supported in UE 5.0. https://dev.epicgames.com/documentation/en-us/unreal-engine/optimizing-rendering-with-pso-caches-in-unreal-engine (R)
- "Six frames at 60 fps" = 100 ms / 16.7 ms. (C)
- Unity Application.backgroundLoadingPriority: Low 2 ms, BelowNormal 4 ms (default), Normal 10 ms, High 50 ms; player only; UWP default High, consoles default Normal, others BelowNormal. https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Application-backgroundLoadingPriority.html (R)
- Addressables: reference count per asset and per bundle; bundle unloads at zero; cannot unload part of a bundle; warning about releasing the last item then reloading from the same bundle. https://docs.unity3d.com/Packages/com.unity.addressables@2.3/manual/MemoryManagement.html (R)
- Unity AssetBundle compression: LZMA smallest and decompressed whole; LZ4 near-uncompressed load times with chunked access; uncompressed fastest; cache converts LZMA to LZ4 on download. http://docs.unity3d.com/6000.0/Documentation/Manual/assetbundles-compression-format.html (R)
- Unity GraphicsStateCollection: BeginTrace/EndTrace/SaveToFile, .graphicsstate, development builds only, experimental, trace per graphics API and platform, ContainsVariant. https://docs.unity3d.com/6000.0/Documentation/Manual/shader-pso-trace.html (R)
- Godot 4.4+ ubershaders, specialization constants, load-time precompilation, Forward+ and Mobile only, Compatibility excluded, hidden node for spawned effects, features to enable early, pipeline monitors. https://docs.godotengine.org/en/stable/tutorials/performance/pipeline_compilations.html (R)
- Godot ResourceLoader: load_threaded_request(path, type_hint, use_sub_threads, cache_mode), load_threaded_get_status with progress array, load_threaded_get blocks if not ready, status enum values, use_sub_threads note about main-thread slowdown. https://docs.godotengine.org/en/stable/classes/class_resourceloader.html (R) and https://docs.godotengine.org/en/stable/tutorials/io/background_loading.html (R)
- Godot: instantiate()/add_child() of a big scene runs on the main thread and can hitch (pitfall text). General engine behaviour, not stated on the pages above. Fact-checker to confirm. (C)
- DirectStorage on Xbox: 50,000 IOPS for 5 to 10 percent of one core; 2.0 GB/s minimum over 250 ms; submit all requests, do not hold back; read-size guidance 32 to 64 KiB on NVMe; queue capacity at least four times per-frame requests. https://learn.microsoft.com/en-us/gaming/gdk/docs/features/console/storage/directstorage/directstorage-overview?view=gdk-2604 (R)
- DirectStorage 1.1: GPU decompression, GDeflate, independent 64 KiB tiles; vendor metacommands with DirectCompute fallback. https://devblogs.microsoft.com/directx/directstorage-1-1-now-available/ (R)
- Insomniac (Mike Fitzgerald, Director of Core Technology): the SSD and I/O get any texture or resource into memory almost instantly; frees memory budgeting. https://www.playstation.com/en-au/editorial/how-ps5-helped-make-ratchet-and-clank-rift-apart-possible/ (R, paraphrased; the fetched wording is the tool's summary, check the page)
- Rift Apart on a hard drive stutters or freezes in the portal sequence (interview answer, senior question 3): from search summaries of Digital Foundry's PC port testing reported by VGC, https://videogameschronicle.com/news/video-shows-ratchet-clank-pc-port-struggling-to-run-on-a-ps4-hdd (S, not read). Fact-checker: read it or drop the claim.
- Rift Apart PC port uses DirectStorage 1.2: https://www.techspot.com/news/99392-ratchet-clank-rift-apart-pc-use-directstorage-12.html (S). Not used in the draft text except as general DirectStorage context.
- Unreal World Partition: single persistent level split into grid cells, streaming sources, one file per actor, data layers, HLOD. https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine (R). Default cell size and loading range numbers from the summariser (256, 768) were uncertain and are NOT used in the draft.
- Google Play size limits (compressed): asset pack 1.5 GB; install-time total 4 GB; on-demand and fast-follow total 30 GB. https://support.google.com/googleplay/android-developer/answer/9859372?hl=en (R). ## Changes after the fact-check (2026-10-05)

R = page fetched in this pass (the fetch tool summarises, so wording is paraphrase); F = taken from the fact-check, which read the raw page; C = judgement or arithmetic.

- WRONG fixed: App Store executable __TEXT limit. facts[8] now says 500 MB for the total of all __TEXT sections for iOS 9 and later, and no longer gives 80 MB. https://developer.apple.com/help/app-store-connect/reference/app-uploads/maximum-build-file-sizes/ (F, and the raw page in this pass confirmed a 500 MB figure with the footnote "total of all __TEXT sections"; the summariser's reading disagreed, the older-OS rows were not used).
- OUTDATED fixed: On-Demand Resources is now called legacy; the draft names Background Assets with Apple-hosted asset packs (how[11], TECH[9]). https://developer.apple.com/documentation/foundation/nsbundleresourcerequest (deprecation note, F) and https://developer.apple.com/documentation/backgroundassets (page exists; its body was not readable in this pass, so the claim rests on F).
- UNSUPPORTED softened: Godot map line now says Godot "does not expose a per-frame cap like Unity's (the docs do not describe one)". No source; labelled as absence in the docs (C).
- Code: Godot snippet now matches THREAD_LOAD_INVALID_RESOURCE with FAILED, so a bad path no longer polls forever. https://docs.godotengine.org/en/stable/classes/class_resourceloader.html (F). Unity snippet unchanged (no defects found).
- Teaching 1: Unreal PSO precaching named first, bundled cache second. https://dev.epicgames.com/documentation/en-us/unreal-engine/pso-precaching-for-unreal-engine (R: compiles PSOs asynchronously after component load; drawing is skipped by default until ready; precaching also leaves the driver cache warm; the bundled cache is the manual play-through route). - Teaching 4: opening sentence of why[0] now says phones terminate the process and consoles usually fail an allocation (F; Apple's os_proc_available_memory page is the only cited source for the phone half).
- Play download warning: why[4] now says "over 200 MB on mobile data", non-blocking. https://support.google.com/googleplay/android-developer/answer/9859372 (F).
